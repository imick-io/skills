The issue is a **Run ticket**: it names a suite file in `test-suites/` (read `test-suites/README.md` for the format). Read the issue (`gh issue view {{ISSUE}} --comments`) and the suite file, then run the suite the way its `runs-via` says:

- **`sandbox`**: run its `command` from the repo root, with a time limit a little above its `takes`. When the project has a `.sandcastle/sandbox-env`, `source` it first: the services are already running. Don't install or start your own. A suite that takes under 8 minutes runs in the foreground (`timeout 480 <command>`). A longer one runs detached with its output in a file (`nohup timeout 3600 <command> > /tmp/suite.log 2>&1 & echo $! > /tmp/suite.pid`), and you wait for it as below.
- **`workflow <file>`**: first look for a run already started on the commit under test, by an earlier attempt at this ticket: `gh run list --workflow <file> --branch {{REF}} --commit {{SHA}} --limit 1 --json databaseId,status,conclusion,url`. If one is in progress, or finished after the ticket's last report, use it. Otherwise start one (`gh workflow run <file> --ref {{REF}}`) and find its id with the same `gh run list`. Read the failed jobs' logs with `gh run view <id> --log-failed`.

**Waiting.** The loop stops an agent that prints nothing for 10 minutes, so wait in steps of at most 8 minutes, each its own foreground command, and repeat until the run finishes: `timeout 480 gh run watch <id> --exit-status > /dev/null; gh run view <id> --json status,conclusion` for a workflow, or `timeout 480 sh -c 'while kill -0 $(cat /tmp/suite.pid) 2>/dev/null; do sleep 15; done'; tail -5 /tmp/suite.log` for a detached sandbox run. Never put a wait in the background and end your turn to wait for a notification: none comes in the loop, and the run is cut off and its result lost.
