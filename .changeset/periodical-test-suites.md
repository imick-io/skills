**Slow test suites run through tickets, not on every PR.** A repo's `test-suites/` folder holds one file per slow or special suite (a 30-minute backtest, an Android e2e that needs an emulator): its command, the paths it covers, how long it takes, and who can run it (`sandbox`, a GitHub `workflow`, or a `human`). `/to-tickets` adds a **Run \<suite\>** ticket to an epic whose slices touch what a suite covers, blocked by every other ticket so it runs last; the agent loop adds any the epic's real diff calls for before it opens the PR. The loop runs the ticket (or starts the workflow and waits): green closes it with the commit tested, red files bugs it then waits on. The epic's PR opens only once its suites passed. The tracker gains a **Test suites** tab: each suite, its last green run, and whether it's **stale** (commits to `main` touched what it covers since), with the command to file a run against `main`; a stale suite is also an action item. New label `suite-run`; `/setup-imick-skills` gets a Section I for it.

**CI that skips what didn't change.** `setup-imick-skills/ci-change-gates.md` documents the shape for a Turbo monorepo: a `changes` job (`turbo --affected` plus `dorny/paths-filter`), the expensive steps (services, e2e, browsers) gated on its outputs, and one always-running `ci-ok` job as the single required check, with the pitfalls (a shallow checkout or missing `TURBO_SCM_BASE` silently runs everything; a workflow-level `paths:` filter leaves a required check pending forever; a Turbo graph missing a cross-package link skips tests that should run). `/update-imick-skills` reports three new CI issues with fixes: `no-change-gate`, `paths-on-required` and `no-aggregator`, and copies `test-suites/README.md` into projects on the loop or the epic workflow.

Existing setups: `/update-imick-skills` does it (new `main.mts`, `suite-prompt.md` and `plan-prompt.md` in `.sandcastle/`, `tracker/build.mjs`, the `suite-run` label and row, `test-suites/README.md`), then restart the loop. By hand: copy those files, add the `suite-run` row to `docs/agents/triage-labels.md` and `gh label create suite-run --color 0052CC`. For a suite run via a workflow, give the loop's `GH_TOKEN` **Actions: read and write**; for the hosted tracker's new tab, give its `GITHUB_TOKEN` **Contents: read**. Then write one `test-suites/<name>.md` per slow suite (the README says how) and, if that suite ran on every PR until now, drop its `pull_request` trigger.
