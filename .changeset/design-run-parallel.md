`/run-design-epic` is faster. Rounds 2 and 3 are re-checks: they re-photograph only the pictures the last review named and the screens the fixes changed (every screen again when a fix reaches shared components), and the review page shows each screen's latest picture across rounds. And a project whose `docs/agents/design-capture.md` has a `Lanes` section (a second copy of the app's stack, with its own ports, database and queue) can run two tickets at once, paired so they don't collide; `design check` reports `lanes`. Without that section, a run is one ticket at a time, as before.
